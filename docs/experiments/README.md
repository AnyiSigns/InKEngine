# 实验/测试报告目录约定

本目录集中存放 Inkling 与 ink_engine 全部实验、测试、验证报告（含真实模型证据）。
目录按**任务类型（区域）**组织，不按模型；模型作为报告字段出现。

## 区域目录

| 目录 | 区域 | 示例实验 |
|---|---|---|
| `self-learning/` | 自学习/执行闭环 | 复杂项目基准 live（真实 agent 改→测迭代） |
| `regression/` | 全机制回归 | e2e live 套件全量重跑（304 用例） |
| `sandbox/` | 沙箱/权限/审批/工具门禁 | 工具沙箱提取器、审批链、fail-closed 实验 |
| `os/` | OS 感知/操作 | OSWorld 风格元素树+点击评测（simulated/live） |
| `memory/` | 记忆/知识/检索 | 预留 |
| `frontend/` | 前端/显示层 | 预留 |
| `chains/` | 链级连通性实验 | agent 链逐环节断言（真实链 import + 驱动） |

新区域出现时在 README 登记后再使用。

## 文件命名

`<实验名称>-<模型>-<YYYYMMDD>.md`（同实验同日多跑加序号；无模型的实验模型字段写「无」）。

## 每份报告必含字段

1. **实验/测试名称**
2. **实验效果**（指标：成功率/通过率/轮数/耗时等，含达标线对照）
3. **实验时间**（起止时间、耗时）
4. **实验模型**（model id）
5. **相对文件路径**（实验脚本/产物/套件报告，相对仓库根）
6. **执行命令**（可复现；含环境变量名，不含 url/key 值）
7. **失败明细与分类**（机制缺陷/任务集缺陷/模型行为/环境错误）与根因

## 红线

- **不落盘任何 url / api key / 密钥**（含命令块；端点来源统一写「.kilo/测试模型配置.txt」）。
- 报告必须可复现、经得起质疑：给出命令、环境（python 版本、git HEAD）、指标口径与达标线。
- 数据不粉饰：失败如实记录、分类归因，未达线必须给根因。
