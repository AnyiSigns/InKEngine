## 〇、缘起与反思结论（本稿要修正的三个认知）

1. **组装不是每轮的动词**。P4 会话级骨架定案后，回合沿骨架推进是常态；
   旧稿残留的「按轮观察图/按轮组装」表述与骨架模式冲突。本稿定案：组装是
   **离散结构事件**，只发生在两个时点（首个真目标 / 演化采纳后），见 §一.2。
2. **「每轮重组装 = 多样化」与结构学习互斥**。结构每轮都变，回合结果就无法
   归因到结构——跨会话择优就成了空话。**归因优先**，所以「一个会话 = 一个
   图生命周期」不是妥协，是结构学习成立的前提。多样化的主战场是**跨会话**，
   不是回合内。
3. **现状 ≠ 愿景要分账**。现状引擎组装器（`_forward_search`）只产**线性链**，
   无分支/回环/层级搜索空间；监督/工作流/嵌套拓扑不存在于生成侧。本稿不承诺
   「拓扑搜索涌现」，改走**受审模板 + 槽位填充**（§一.5）——模板是资产，
   组装只做实例级填充。

另：本轮对话澄清的词义冲突已收敛为术语表（§一.9），后续文档/代码注释一律
按表用语，避免「组装/推演/展开/进化/孵化」一词多义复发。

## 一、大设计（语义收敛定稿）

### 1.1 会话 = 一个 agent 实例的图生命周期

**核心对象不是「图」也不是「回合」，是会话**：一个 agent 实例从建图到
checkpoint 收尾的完整生命周期。图是该生命周期的结构载体。

- 身份边界恒一：会话期间事件/记忆/审计/产物统一归该 agent；
- 无论内部是线性、工作流还是监督团队，对会话外只呈现一个 agent；
- agent = 递归展开：图里的 `kind=agent` 结点展开又是子图（`§2.3 已有`），
  递归无上限但受深度护栏约束；
- 会话尺度数据 = 骨架/游标/当前执行态（随 thread checkpoint 恢复）；
  演化产物永不「专属本会话」（进化即留存不变量，继承旧稿）。

### 1.2 组装 = 低频离散结构事件（替代「按轮组装」）

图结构只在两个时点被构造/修改：

| 时点 | 动作 | 说明 |
|---|---|---|
| **t0 首个真目标出现** | 架构选择 + 模板槽位填充 + 校验 → 会话图（骨架）落地 | 问候/闲聊等无任务回合**不触发**（分诊门，§一.3） |
| **tN 演化采纳后** | 局部改骨架（声明式）或重组装（新资产入池） | 采纳 = 受控事件（审批/补丁链），非默认节拍；自续跑 carry 此语义 |

其余回合一律**沿图推进**：`active_target` 游标移动、router 分支、条件边
选向、LLM 判定执行——图结构冻结，只有行为不确定。

### 1.3 分诊门（新首步）

组装触发条件不是「用户发了消息」，而是「出现了值得一张任务图的目标」：

- **无目标回合**（你好/闲聊/澄清）：走最小形态——单终态结点直接回复，
  零架构决策、零模板填充、不建立任务骨架；
- **有目标回合**：进入架构决策（§1.4）→ 建图。
- 判定分级（由轻到重，取先命中）：静态启发（输入空 schema/问候特征）
  → 可配置 planner 判定（复用 llm 实例，成本档位可关）。
- 与现状兼容：当前引擎对空目标已有回落语义
  （`assembler.ts` goal 为空返回 fallback_reason）——分诊门是把该语义
  提升为**显式首步**，并把「建图时机」从「会话第一条消息」改为
  「首个真目标」（问候开局时二者不同）。

### 1.4 架构 = agent 内部组织模式

架构不是第四类构件，是**会话图的组织形态**，全部在 agent 身份边界之内。

**模式集 = 三种组织模式 + 一个递归轴**（不引入第四种平级模式）：

| 模式 | 判别特征（拓扑） | 触发线索（目标分析输入） |
|---|---|---|
| 线性 | 无分支无环链 | 单意图、无质量门、无并行需求 |
| 工作流 | router 条件分支 / 门回环（检查→返工） | 多子任务需分派、需确定性流程门 |
| 分级监督 | 监督者 + 多 worker + 审阅回边 | 质量关键、可并行分解、需终审 |
| （嵌套 = 递归轴） | 任意模式的结点是 `agent` 子图 | worker 自身复杂需再分解；由递归提供，不是并列模式 |

**选择时机**：t0 建图时（会话级）；每个 `agent` 结点展开时**可再选一次**
（与「召唤 = 挂 agent 结点并展开内部回路」同构，选择随递归下钻）。

**选择权限分层**（低到高，高者覆盖低者）：

1. 算法启发（默认）：静态特征→触发线索表→模式；
2. agent 声明：声明式改骨架时携带 `structure` 意图，经 `validate_skeleton`
   校验后生效；
3. 用户显式：最高优先，会话/线程级覆盖。

**降级链（护栏）**：所选模式的槽位无法从池满足 → 不硬拼，沿
「分级监督 → 工作流 → 线性 → 单终态兜底」逐级降，降级原因入审计。
架构是意图不是承诺。

### 1.5 架构模板机制（P5 核心新机制）

监督/工作流等拓扑**不做搜索涌现**，做**受审模板**：

- **模板 = 资产**（数据），字段含：`structure_type`、槽位定义（每个槽位的
  契约要求/允许多实例/worker 数范围）、图不变量（回边要求/终态可达/
  监督者必达终审）、校验规则、降级链、`origin`（seed/host/agent/governance）、
  `status/version`——**形状对齐池治理登记行与实体目录**；
- 模板只定**结构空位**，执行体仍只能来自池（宿主/内置/包绑定）——不引入
  运行时任意代码，继承旧稿不变量 7；
- **来源**：出厂三模板（线性/工作流/分级监督最小可执行版，含验证用链，
  参照 P4.2a 出厂池种子扩充的先例）；agent/宿主/包可注册新模板，走
  审批 + 补丁链（复用「新类型/新 agent 诞生边界」的闸门语义）；
- **槽位填充**：模板实例化时，组装器在槽位内做契约匹配（复用现有
  contract pool 视图 + beam，但搜索被模板约束到槽位，而非全域链搜索）；
  同一 kind 多实例分化（如 planner/reviewer 写不同输出键）是槽位可满足性
  的前提——池里无分化实例 = 该槽位不可满足 = 触发降级链。
- 模板变化本身可随会话结构档案的跨会话择优结果演化（§1.7）。

### 1.6 展开三通道 = 同一子作用域基座的三个提交契约

代码事实：`spawn`（`run_spawned`）、决策点推演（`run_simulated`）、会话试跑
（`fork_trial`）共用同一实例化基座（子引擎 + 独立 checkpoint 子链 + 事件汇
入父链 + 成本护栏），**唯一差异是结果提交契约与作用域尺度**。本稿不新增
机制件，只做术语收口与角色升级：

| 通道 | 提交契约 | 作用域 | 用途 |
|---|---|---|---|
| spawn | **全部回流** | 图中一段子图 | 并行干活，子任务结果全要 |
| 决策点推演 | **择优回流** | 决策点候选分支 | 不确定走向先跑后选，落选保轨迹 |
| fork_trial | **不回流（只给决策）** | 整个会话（骨架+消息基线） | 会话级假设验证，主线不动 |

统一伞词：**展开**。三问定通道：结果要不要回来 / 边界多大 / 谁发起。

**fork_trial 角色升级（本稿新增语义）**：作为「演化采纳前验证闸」——
agent 自修改提案落地主线**之前**，先 fork 试跑一轮；试跑线程的胜负
**不进主线证据**（归因保险，与探索预算「试跑样本不污染统计」同构）。
试跑采纳后才经重组装上主线。

### 1.7 演化双入口 = 同一资产层同一条受控通道

| 入口 | 驱动 | 路径 | 示例落点 |
|---|---|---|---|
| 进化（有意） | agent 决策 | 提案 → 审批 → 补丁链 → 采纳后（重组装/自动续跑）生效 | self_tools / apply_patch |
| 孵化（无意） | 回合事件统计累积 | 信号 → 孵化缓冲 → 变异/结晶 → 受控落资产 | entity_evolution / 知识孵化 / skill_crystal / growth / tuning |

- 两条入口**不各建一套池**：变异与补丁走同一受控通道（GuardedStorage /
  EvolutionWriter / 补丁链 + 审计），落同一资产层；下一轮组装两种变更都读
  得到——「会话内下一轮生效 / 跨会话生效」对二者同样成立；
- 「进化即留存」覆盖**双侧**：孵化产物同样不许只活在会话里；
- 结构变更（新架构模板/骨架形态变化）属于进化侧，须审批；孵化侧只动
  池内实例先验/技能/实体 meta，不动结构模板形态。

### 1.8 归因与跨会话择优 = 结构学习的第一性问题

会话 = 一个结构 → N 个推进回合结果的**对照单元**：

1. 推进回合证据（节点成败/边证据）归本会话图（现状已如此）；
2. 会话收尾 → 沉淀**会话结构档案**：`structure_type + 组合指纹（结点/边实例
   清单）+ 结果统计（成功/失败/轮次/预算消耗）`——随 checkpoint/records 落库；
3. 跨会话在**结构档案**上择优：同 type 不同组合的档案互为对照 → 模板先验
   更新/模板废弃/槽位分化建议 → 经受控通道反馈池与模板目录。

这给「组装 = 不确定 = 多样化」以正确落点：**多样性发生在跨会话的建图点**
（每次建图是一次结构实验），回合内不再乱组。

### 1.9 术语收敛表（文档/代码注释统一用语）

| 词 | 指代 | 不指代 |
|---|---|---|
| 装配 | 引擎自身启动（Runtime 装配 ①–⑰） | 图结构构造 |
| 组装 | 图结构构造（t0 / 演化采纳后） | 引擎启动、agent 结点展开 |
| 推进 | 回合沿会话图执行（常态） | fork 试跑 |
| 展开 | 子作用域执行总称（spawn/推演/fork_trial） | 组装 |
| 推演 | 决策点 run_simulated（择优试跑） | 正常回合 |
| 会话试跑 | fork_trial | spawn |
| 进化 | 有意自修改（审批后落资产） | 统计变异 |
| 孵化 | 无意统计变异/结晶 | 有意自修改 |
| 演化 | 进化+孵化落资产的总称 | — |

## 二、关键语义裁定

1. **建图时刻**：首个真目标出现时建图；问候开局 = 先走最小形态，目标出现
   才升级建图（骨架空/不满足的回落语义继承 P4）。
2. **结构冻结是特性**：会话图生命中期不重建；结构变更只经演化采纳点。
3. **架构选择落点**：决策结果写入会话骨架（新增可选字段 `structure`），
   随 thread state 持久、可审计、可被声明式修改覆盖。
4. **模板槽位可满足性 = 池实例分化度**：同类多实例（不同用途/不同契约输出
   键）决定复杂架构能否成立；池无分化 = 降级，不臆造。
5. **试跑与证据隔离**：spawn/推演/fork_trial 分支与试跑线程的胜负不进主线
   证据与指纹缓存（继承 P4.1 兜底零强化/试用样本不污染统计的同一原则）。
6. **作用域模型覆盖（待实施缺口）**：协作者/agent 结点的 `model` 引用要
   在展开时作用于子作用域内 llm 调用——现状 llm seam 为宿主注入单例，需
   在展开器加 per-scope override（P5-E）。
7. **协作者定位**：实体目录 = 数据真源（persona/model/role 跨会话持久）；
   图内每次出现 = 挂 `agent` 结点实例化；运行时动态临时协作者走 spawn 通道。

## 三、落地蓝图（P5 队列，待 `graph_type_system_design.md` P4 收尾后排期）

依赖总览：P5-A/D 依赖 P1–P4（登记行 kind/flags、骨架、validate_skeleton、
auto 续跑）；P5-C/E/F 依赖 P5-A/D 语义；P5-G/H 依赖前序稳定后置。每阶段独立
验收、独立 commit/PR。

### P5-A —— 分诊门 + 组装触发语义收敛（engine core）

- `_runtime_rounds`/组装入口前显式首步：回合输入 → 分诊（无任务目标 = 最小
  形态单终态回复；有目标 = 建图/沿图推进）；把「首个真目标建图」与
  「会话骨架缺失走组装建立」合并为同一语义。
- 改动面：runtime rounds + assemble seam + 相关测试。
- 验收：`vitest run --root engine`、`tsc -p engine/tsconfig.json`；新增测试：
  问候首条不建任务骨架、目标出现升级建图、无目标回合走单终态。

### P5-B —— 架构模板数据面 + 模板目录（engine core 数据面 + 受控注册）

- 模板类型/登记（对齐 node_registry 形态）+ 出厂三模板种子（线性/工作流/
  分级监督最小可执行版，含验证用链——参照 P4.2a 先例）；模板走审批 + 补丁
  链注册，注册行入治理登记（继承 pool_governance 语义）。
- gated docs 同步 + 架构门禁扫描。
- 验收：引擎单测 + `tsx gate/src/check.ts`。

### P5-C —— 架构选择决策器（分层：算法启发默认 / agent 声明覆盖 / 用户显式）

- 算法启发 = 静态特征 → §1.4 触发线索表（不引入必选 llm 前置步骤）；
- agent 声明 = `skeleton.edit` 携带 `structure`，经 `validate_skeleton` 挂载；
- 降级链实现：槽位不可满足 → 逐级降 → 审计记录降级原因。
- 验收：架构选择确定性测试（同输入同选择）、声明覆盖、降级链逐级断言。

### P5-D —— 槽位填充组装器改造（engine path_assembler）

- 模板实例化入口：把 `_forward_search` 约束到模板槽位（槽位内契约匹配 +
  beam），保留线性链原路径作为「线性模板」特例（向后兼容，旧图 digest 不漂移）；
- 分支/回环图合法性校验按架构规则（复用 executor 已支持的 conditional/loop
  执行语义——P4.2a-2——生成侧补齐）。
- 验收：线性回归（既有确定性断言不变）+ 工作流/监督模板最小实例化 + 非法
  槽位降级。

### P5-E —— 作用域模型/persona 覆盖（展开器 seam override）

- `agent` 结点/spawn 实例展开时，子作用域内 llm seam 按结点 config 的
  `model` 引用覆盖（null = 继承会话默认）；协作者目录 model 字段就此生效。
- 改动面：executor 实例引擎构造 seam、node seams 注入点。
- 验收：per-scope 覆盖单测 + host 集成（不同 model 引用落到不同 adapter 配置）。

### P5-F —— 采纳前验证标准化（fork_trial 接入自修改工具面）

- 自修改/进化提案 →（可选）`rounds.fork_trial` 试跑 → 采纳才重组装上主线；
  试跑结果不入主线证据/指纹（归因保险）。
- 验收：host 集成测试——提案 + 试跑 + 采纳链路、试跑失败不采纳、证据隔离断言。

### P5-G —— 会话结构档案 + 跨会话择优（engine 沉淀侧）

- 会话收尾沉淀结构档案（structure_type + 组合指纹 + 结果统计）；跨会话在档案
  上择优 → 反馈模板目录先验/废弃建议（经受控通道）。
- 验收：档案字段往返、同结构多会话对照择优、择优结果入模板目录先验。

### P5-H —— 演化沉淀时间线双轨 UI（承接 evolution_feed 职责）

- 孵化 + 补丁双轨合一动态时间线 + 协作项目录只读；等 P3 状态页稳定 + 前序
  P5 沉淀数据形态定型后实施。
- 验收：插件单测 + `verify_unload` 孤儿扫描 + `sync_plugin_manifest` check。

## 四、兼容约束与不变量

1. 线性模板 = 既有链式组装的同义封装，序列化/digest 不漂移（回填不外溢）；
2. 骨架扩展字段一律可选，旧 checkpoint 反序列化回落旧语义；
3. 模板只定结构空位，执行体只能来自池/宿主/包（运行时无任意代码）；
4. 试跑/分支/推演信号不进主线证据与指纹缓存；
5. 会话图生命中期结构冻结；结构变更只经演化采纳点（受控）；
6. 架构不可满足走降级链，不臆造图（诚实空态原则继承）；
7. 术语按 §1.9 表，文档与代码注释禁旧歧义用法。

## 五、口径决议记录

1. 会话 = 一个 agent 实例的图生命周期；全部架构形态在 agent 身份边界之内。
2. 组装是离散结构事件（首个真目标 / 演化采纳后），非每轮动词；常态 = 沿图推进。
3. 问候/闲聊等无目标回合走最小形态，不触发架构组装（分诊门）。
4. 架构模式集 = {线性 / 工作流 / 分级监督} + 递归轴（嵌套非并列模式）；
   每个 agent 结点展开点可再选一次。
5. 架构选择权限：算法启发（默认）< agent 声明 < 用户显式；选择结果入骨架
   持久、可审计、可覆盖。
6. 监督/工作流拓扑做受审模板 + 槽位填充，不做搜索涌现；模板 = 资产走
   审批 + 补丁链；槽位不可满足走「监督→工作流→线性→单终态」降级链。
7. spawn（全回流）/ 推演（择优回流）/ fork_trial（会话假设不回流）= 同一
   子作用域基座的三个提交契约，统一伞词「展开」；不新增机制件。
8. fork_trial 升级为「演化采纳前验证闸」；试跑胜负不进主线证据（归因保险）。
9. 进化（有意）与孵化（无意）双入口落同一资产层同一条受控通道；「进化即
   留存」覆盖双侧。
10. 归因第一性：会话 = 结构对照单元；会话收尾沉淀结构档案；跨会话在档案上
    择优反馈模板目录——多样化主战场是跨会话建图点。
11. 术语收敛按 §1.9 表执行。
