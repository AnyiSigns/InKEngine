# InkEngine 概念文档

引擎的心智模型：**「机制是引擎，知识是数据，变化是补丁，汇入靠调配」**。
本文档按概念介绍引擎的独创体系，作为框架心智模型与宣传点；机制在
`ink_engine/core`（engine-core，纯机制唯一 seam，架构门禁保证零领域词/
零宿主词），领域深度归宿主产品层（领域规则/样例/谓词由产品自写并成对
维护，机制层只带通用种子与 boot 自举基线）；Forge（text_forge_evo）与
stdio_host 作为宿主消费方，读取 core API 与自举数据组装自身流程，
不复写机制；`examples/` 附可独立运行的示例。

## 卡回路（Review Loop）

agent 与用户协作的基本回路：**执行 → 弹卡 → 用户裁决 → 注入重入**。

- 引擎一等能力 `interrupt`：节点执行到边界可声明中断点（四类卡：
  gate 落库确认 / body 消息体 / audit 审核 / candidate 候选），执行暂停并
  持久化；外部注入裁决值后从该节点重入（`ctx.interrupt(key, payload)`）。
- 弹卡即收集偏好数据（accept/reject/edit = 最真实奖励信号，评审-收敛
  的奖励来源之一）。
- 工具调用前挂卡有标准姿势：`approve_before_execute`/`approve_batch`
  （`core/approval.py`）——gate 卡的标准包装，挂起/注入/重入走
  interrupt 原语，宿主不必自写挂卡实现；决议集 accept/edit/reject/
  terminate/auto，超时或非法注入一律回落 reject（fail-closed 兜底）。
- 行为语义（拒绝转讨论/重试止损/挂起卡保留）由业务层编排，引擎只提供机制。

## 交互时间线（Interactive Timeline）

一切执行都是**时间线**：事件流 append-only（执行日志）、回合步骤序列
（step_id/round_id 天然有序）、checkpoint 版本链（节点快照）。

- **断线续流**：快照 + 增量日志重放；
- **编辑重放**：日志截断 + 新分支（`regenerated_from` 标记失效区）；
- **轨迹树**：parent_step_id 显式化步骤父子关系，回溯「哪个决策导致什么结果」；
- **轨迹分叉**：补丁链 `branch` 派生共享前缀的新链（What-if 平行宇宙），
  不物理改动原链。

## 发散-收敛（Diverge-Converge）

创意生成的并行机制：同一请求并行产出 N 个候选（发散），再聚合挑选
（收敛）。

- **发散** `fan_out(tasks, limit)`：并发原语 + 变体指令注入 + 部分失败剔除
  （成功入候选集，失败注明），成本护栏（变体上限）。
- **收敛**：候选选择卡（source 分流 workflow/divergent），「挑选即确认」
  落库语义——候选卡已承担确认，不再重复弹 gate 卡。
- **段落级混合（进阶）**：候选 = 段落级补丁，收敛支持跨候选取段落组装
  （变体 A 开头 + 变体 B 结尾），由评审器段落级评分驱动。
- **候选锦标赛（可选）**：候选较多时两两评审淘汰（N-1 次比较）。

## 决策点推演-回溯-换选（Simulate）

关键决策点不直接拍板，而是**推演多种走向再择优**：节点返回
`__simulate__` 分支清单，引擎把每个分支作为独立子链执行（与 spawn
同构：隔离状态 + 独立 checkpoint 链 + 事件统一父链），执行结果经
评估器协议打分，调配策略择优提交主线。

- **择优不止单选**：多个分支结果 = 源、评估分 = weight、主线上下文
  预算 = 预算——选优或跨分支组装（分支 A 的部分 + 分支 B 的部分），
  组装留痕记录「哪部分来自哪个分支」；
- **落选分支不销毁**：保留为轨迹树引用（分支事件 parent_step_id 指向
  决策点步骤）——可回溯对比/换选；分支失败/评估失败按部分失败语义
  剔除，全部失败按节点失败收口（不静默提交空结果）；
- 评估器协议在引擎（core），评审策略由使用方注入（规则集/加权打分器）。

## 运行时重规划（Planner Loop）

图拓扑成为 LLM 可改写的数据：节点返回 `__plan__` 下一跳编排清单
（节点序列 / 并行组 / 条件 / spawn 子任务），引擎执行一段后重规划。

- **计划版本化**：计划 = checkpoint 快照字段（随版本链落盘与回滚）——
  回溯决策点时计划与状态一起回到当时版本，推演锚点不失效；
- **与 `__spawn__` 共存**：计划 = 流的结构（下一跳编排），spawn = 流
  的展开（并行子任务），可嵌套；计划 spawn 步同受 max_spawns 护栏
  约束、error_on_exception 统一配置驱动；
- **图即数据**：图 = 可序列化声明数据（节点/边以注册名引用），指纹
  版本随 checkpoint 落库；harness 仓库按补丁链版本承载图定义，回退
  可取旧图（图版本校验只作用于 resume_from 真恢复，续链不校验）。

## 核声明式化（Rules as Data）

校验/评审语义从代码函数降级为**声明式规则数据**：规则 DSL（受限、
schema 约束）+ 通用机制骨架（约束检查器/加权打分器/schema 校验器/
状态机）。

- **规则 DSL**：不变式/校验规则/状态转换规则，LLM 生成比代码安全可控；
  谓词 = 注册函数（可测试/可审计），规则 = 数据（可版本化/回退/导出导入）；
  内置谓词 13 个（present/absent/equals/compare/in_enum/unique_pairs/
  state_transition 等），点分 target_path 提取（私有段一律拒绝）；
- **样例库机制**：每个知识集自带 fixtures，新规则必须先让 fixture 全绿
  才允许落库（非谈判项；失效跳过判失败，防静默失效骗过闸门）；
- **混合判定**：确定性规则引擎跑声明式规则（快/可测/可审计），规则
  覆盖不到的深度启发式退回 LLM 判定（fail-open）。

## 知识集孵化（Knowledge Incubation）

知识集 = 在记忆原语与补丁链之上的封装层：**规则条目 = 补丁链数据**
（演化 = 新补丁，回退 = 旧版本，分支 = 平行版本）。

- **信号感知**：任务执行轨迹中分类感知五类信号——踩坑（预期外失败）/
  用户修正（卡回路反例）/ 洞见（成功路径经验）/ 流程缺口（新建候选）/
  重复根因（同一问题 ≥3 次 → 人工确认后升级修规范）；触发条件 =
  任务复杂度或用户干预超过阈值，蒸馏按需触发非每回合；
- **蒸馏**：把轨迹压缩为结构化知识——丢弃试错分支，仅保留成功步骤/
  分支判断/异常修复；对已有知识的修正走**精准补丁**（replace 语义，
  只改对应段落，不重写整条知识）；**复用优先于生成**（相似任务检索
  命中则跳过蒸馏）；
- **三层验证闸门**：L1 准入（schema 校验 + 安全扫描 + 指令注入检测）→
  L2 效果评估（完整样例库 + 历史回归，全绿才进下一层）→ L3 目标筛选
  （不差于旧版且至少一维严格优于才保留，多样性变体并存供下轮进化）；
- **进化工厂**：低负载窗口批量进化——失败率高的知识优先入队，反思式
  变异（变异输入 = 近期失败日志），变异体同样过三层闸门防退化；
- **分层与晋升**：工作级流水账（append-only）→ 项目级（常用沉淀）→
  用户级（通用教训「毕业」晋升）；晋升 = namespace 迁移，条目 id
  跨层级稳定；种子（只读基线，初始化注入）+ 演化（补丁链）；
- **可移植**：知识集 = 补丁链数据可导出/导入，跨部署迁移复用；来源
  留痕 + 可信度分级（web=0.3 < dialog=0.6 < model=0.7 < user=0.9，
  防 web 注入污染知识集）。

## 自适应调优（Self-tuning）

回合指标聚合纳入引擎自承载（失败率/评审分/收敛轮数/挡位调用），
meta 节点读执行统计自动调整参数（探索宽度/重试预算/web 验证阈值），
知识集权重/阈值随卡回路反馈进化。

- **分工**：调参改参数（权重/阈值），进化工厂变异规则结构（增删改）；
  参数变更过 L2 效果评估回归（参数无「旧版」可比，L1/L3 不适用）；
- **参数快照**：评估时记录所用规则版本 + 权重快照（随评估记录落库）——
  调参不改变历史推演的可回放性，回放/审计按快照重算，避免「标尺在动」。

## 补丁链（Patch Chain，Event Sourcing）

**变化 = 补丁（append-only），状态 = 基础 + 补丁链，取用 = 组装**，
贯穿引擎四层：

- **A. 执行层**：事件流 = append-only 执行日志，checkpoint = 快照，
  恢复 = 快照 + 增量重放，编辑重放 = 日志截断 + 新分支；
- **B. 消息流**：`add_messages` 归约器 = 累积型补丁链（每条消息 = 一个补丁）；
- **C. 状态机**：状态转换 append-only（`StateMachine`），当前状态 = 日志
  推导结果（回溯「这处状态何时变更/由谁变更」；领域状态名由使用方声明）；
- **D. 候选混合**：发散候选 = 段落级补丁，收敛 = 跨候选取段落组装。

内容补丁链原语：`append/replace/delete` + `assemble(full/base_only/partial)`
+ `rebase`（压扁，非破坏性压缩）+ `truncate/branch`（分叉）。

## 输入调配管线（Input Assembly）

调配器从组件升格为执行循环一等原语：**每次 LLM 调用/节点执行前统一
走输入调配**——上下文片段 + 知识集注入 + 工具集裁剪 + 记忆召回 +
证据组装多源在调用点统一调配。

- **统一预算**：一次调用的总预算在多源间分级分配（上下文/知识/工具/
  记忆/证据，默认占比 0.5/0.3/0.1/0.05/0.05）；**能全量则全量，放不下
  才裁剪**——集小（可整集注入上下文）→ 全量激活即最优；集大 → 常驻
  基线 + 任务相关裁剪；工具数独立护栏（max_tools）；
- **统一留痕（激活模式）**：每轮调配的输入 = 「激活向量」——哪些源
  被激活 + 激活强度（weight）+ 版本快照，随调配决定落库——调试/审计/
  调参共用同一份「本次激活了什么」的记录；只记录组装决定不记录全量
  原文（留痕最小化，全量由版本快照重建）；利用率聚合提示过热/过冷；
- **「放不下」的三层处置**：组装期条目级 = 预算裁剪（每调用选子集）；
  组装期条目内 = 摘要视图/非破坏性压缩（CompressionPolicy）；条目
  太大仍大 = 蒸馏时拆分（产出小粒度结构化条目）；
- **统一开关**：行为开关（新旧路径回退）集中一处，一键关回退旧装配。

## 上下文调配器（Context Mixer）

上下文多源注入的「调酒师」：RAG 片段/长期记忆/设定卡/模拟支线/
用户反馈/领域状态，按元数据（来源/权重/相关度/优先级/时效）在预算内融合。

- **确定性层（默认每回合，零额外 LLM 调用）**：预算分配策略接口 +
  WeightedBudgetAllocator（score=weight×relevance：≥0.8 全保留、≥0.15
  截断、低于丢弃），ContextAssembler 加权组装（跨源去重 + 超预算截断 +
  逐源留痕）；
- **LLM 层（按需）**：FusionHook 融合钩子（深度融合/候选语义融合），
  失败自动回退确定性组装（fail-open）；
- **非破坏性压缩**：全量保留，「压缩」= 组装时降级选择
  （base_only/partial/摘要视图），不再物理删除。

## 领域状态层（Domain State）

把领域关键状态从 LLM 隐式上下文移出为引擎可追踪/校验/查询的显式
数据层：状态本身 = 补丁链（每次写操作 append-only，支持回溯/回滚/
分支），校验基于组装后的状态；写时校验语义由领域规则数据提供
（规则集 + 注册谓词 + 样例库，fixture 全绿为落库非谈判项），确定性
判定覆盖不到的深度启发式退回 LLM 判定（fail-open）。

## 工具执行环境（沙箱 + 权限门禁 + 挂卡审批）

工具调用不裸奔：引擎提供「权限门禁 → 沙箱守卫 → 挂卡审批 → 执行 →
审计 → 观察」的完整机制装配（`core/permissions.py`/`core/sandbox.py`/
`core/tool_pipeline.py`/`core/approval.py`），宿主按工具声明权限与
参数语义即可接入，不必自写安全环节。

- **默认拒绝（fail-closed）**：`PermissionGate` 判定权限声明
  （`ToolSpec.permissions`，`domain:action:pattern` 字符串，如
  `filesystem:write:/book/**`、`process:exec:git|python`）；未声明
  权限的工具直接拒绝；判定三路——通过（allow）/ 需审批（review）/
  拒绝（deny），「需审批」委托 `approve_before_execute` 挂 gate 卡，
  门禁自身不挂起；门控分级（L1-L3）由宿主经 `review_tier` 注入。
- **沙箱守卫**：`FileSandbox`（根目录前缀 + resolve 校验 + symlink
  逃逸检测 + 写前快照还原，事务性文件写入底座）与 `ProcessSandbox`
  （白名单命令 + 超时 kill + 输出截断 + 工作目录限定 + 环境变量清理 +
  默认禁 `shell=True`）；`NetworkPolicy` 默认禁网，白名单域名由宿主
  配置。沙箱是机制、非安全边界承诺——默认拒绝兜底 + 纵深防御。
- **执行流水线** `ToolPipeline`：调用前策略（门禁判定，review 委托挂卡）
  → 沙箱守卫（逐个 validate，解析结果回写执行参数——执行对象 = 校验
  对象）→ 单调守卫（可注入，抛异常即拒绝）→ 分发执行（executor 钩子，
  审批决议透传）→ 调用后策略（`tool_audit` 事件留痕，可替换宿主审计
  钩子）→ 结果观察（截断 + 溢出标记）。
- **挂卡审批标准姿势**：`approve_before_execute`（单动作）/`approve_batch`
  （同回合多写聚合一张合并卡）——决议集 accept/edit/reject/terminate/auto；
  `InterruptPolicy` 策略钩子可替换（auto-approve 直过名单、超时窗口），
  默认全挂起 + 不限时；超时默认拒绝（`source=expired`）、非法注入回落
  reject（`source=invalid`），fail-closed 兜底；挂起卡随 interrupt
  checkpoint 持久化，与执行中 cancel 语义互不干扰。

## 自指演化（Self-evolution）

引擎自身形态（图/规则/知识/工具/界面/事件类型/harness/环境/产物）
也是补丁链数据——**引擎观察自己、提案修改自己、经审批后演化自己**，
随机制层走补丁链，不随宿主壳漂移。

- **观察**：`inspect_graph/inspect_rules/inspect_knowledge/inspect_ui/
  inspect_tools` 五元工具（恒定 JSON 信封、函数节点降级视图、快照深拷贝、
  出口统一敏感键剥离），注册进工具表经只读流水线执行（权限
  `introspection:read:*`）；
- **提案**：`propose_patch` 9 类补丁（ui/theme/tool/rule/knowledge/
  harness/event_type/environment/artifact），复用既有校验器
  （UISchemaValidator/RuleSet/HarnessDefinition/…），非法提案建期拒绝；
- **应用**：`apply_patch` 分级审批（L0 策略直过 / L1 弹卡 / L2 沙箱验证
  fail-closed，7 天超时过期回滚）→ 补丁链 append → 活跃态应用（异常只
  告警，重启装配恢复）→ 审计 append-only；`GuardedStorage` 拦截演化
  资产直写（旁路写 fail-closed）；
- **回退**：`revert_patch` 仅链尾单步回退（存储层强制），保持链完整；
- **契约**：SELF_TOOL_CONTRACT 契约清单（9 元工具）随 boot 种子发布，
  单测强制 engine-resident 元工具 ⊆ 清单——换宿主不失明、新宿主直接用。

## 事件与界面即数据（Event & UI as Data）

- **事件类型 = 数据**：`EventTypeSpec` 注册表（name/schema/renderer/
  system/meta），随补丁链持久化——AI 可演化；发射宽松允许（未注册类型
  不阻断，仅折叠标记），schema 违规仅标记（增强非收紧）；system 标记
  类型注入 RunOptions.system_events（不进回合步骤序列）。
- **界面 = 数据**：`ui_spec` 布局树（容器/组件节点 + 绑定通道 + 主题
  token），三层白名单校验（结构 / 组件类型 / 绑定通道与主题 token），
  绑定路径保留前缀（`_`）防内部数据泄漏；前端按同名渲染组件消费，
  事件与组件双 Map 注册表接线。

## MCP 生态（外部生态只经 MCP 消费）

外部生态（插件市场、跨语言执行件、第三方 MCP server）统一经
**MCP 协议**消费：

- `McpServerConfig` 挂载（http/stdio/in_memory 三传输，headers/env
  repr 遮蔽防凭据泄漏），会话生命周期由 `McpClientManager` 管理
  （连接重试/并发串行化/优雅回收）；
- 工具转换纯函数（inputSchema 规范化），权限统一 `mcp:call:<server_id>`
  （按 server 粒度管控），工具进工具表走统一流水线（门禁/审计/观察）；
- **vetting 闸门**：仅 `VERIFIED` 的工具进入工具表，REVIEW/REJECTED
  同样不导入（fail-closed）；
- 语言无关：Python 是引擎实现语言，但数据契约（知识条目 JSON + MCP
  执行件）任意语言均可交付——Rust/TS 等语言以「数据 JSON + MCP 执行件」
  形态提供领域能力。

## 测试时专才化（Test-time Specialization）

不微调权重，靠「生成 → 评审 → 校验 → 迭代收敛」把输出质量逼近专才水平。

- 奖励信号三源：评审器质量评分 + 状态一致性校验 + 卡回路人类反馈；
- 自优化循环：生成器 → 自动评审 → 校验 → 不达标自动再生成（不弹卡）→
  收敛后才呈交卡回路；再生成 = 补丁链新补丁（非破坏性，可回退）；
- 浅层 Beam 搜索：发散 N 候选（Beam 宽度）→ 评审 + 校验打分 → 选优/融合；
- web 验证钩子：评审发现事实存疑 → 触发外部搜索验证 → 结果喂回评审；
- 收敛控制：再生成轮次上限（默认 2 轮），超限呈交现状 + 评审意见
  （卡回路人类裁决兜底）。

## 设计原则速览

1. **确定性编排 + 自主执行单元**：编排层确定性状态机，执行单元自主；
2. **事件即协议**：节点发射的事件流 = 前端协议，无框架事件中间层；
3. **checkpoint 版本链第一公民**：恢复/重放/挂起都是原生操作；
4. **机制通用、策略可插**：机制在内核（唯一 seam），策略在领域/业务层——
   评审策略/调配策略/评估策略/调参策略全部可注入替换；
5. **一切皆数据**：图/计划/harness/工具/规则/知识/参数/分支/事件类型/
   界面描述皆为数据，一切演化皆为补丁链（append-only、可回退、可分支、
   可审计）；
6. **装配动作是机制，装配决策是数据**：换壳 = 换配方，机制层不感知宿主；
7. **OpenAI 兼容优先**：模型层以 OpenAI 兼容协议为基线；
8. **显式化哲学**：上下文显式调配、变化显式留痕、状态显式追踪、
   信息显式管理——把关键状态从隐式上下文移出为引擎可追踪的数据层；
9. **fail-closed 兜底**：凡安全相关判定（权限/沙箱/提取器/vetting/
   审批超时/旁路写）默认拒绝，宁可误杀不放过。
